# ProductsImport — техническое описание проекта

Этот документ описывает текущее состояние приложения: что оно делает, как устроено
изнутри, и какие изменения вносились в исходный код по ходу разработки. Он
дополняет `README.md` (краткая инструкция для пользователя/сборки) более
подробным техническим разбором и полной историей правок.

---

## 1. Назначение

`ProductsImport` — Windows-приложение (WinForms, .NET Framework 4.8), заменяющее
ручной запуск T-SQL скрипта импорта товаров. Пользователь открывает прайс-лист
или накладную в формате Excel (`.xlsx`/`.xls`) или `.csv`, сопоставляет колонки
документа с полями справочника товаров MS SQL Server и запускает импорт. Все
шаги — подключение к БД, сопоставление колонок, значения по умолчанию, разбор
проблемных штрих-кодов, результат — находятся в одном окне, а не в цепочке
отдельных диалогов.

Целевые таблицы БД: `ass1`, `ass2`, `ass3`, `ass4` (карточка товара), `gru2`
(группы), `cls2` (единицы измерения), `nds1` (налоговые ставки/НДС).

## 2. Технологический стек

| Компонент | Выбор | Причина |
|---|---|---|
| UI | WinForms, .NET Framework 4.8 | требование заказчика; весь интерфейс собран кодом (без `.designer.cs`), окна позиционируются абсолютными координатами |
| Доступ к SQL Server | `Microsoft.Data.SqlClient` 6.0.1 | современный, поддерживаемый драйвер, работает на net48 |
| Чтение Excel/CSV | `NPOI` 2.8.0 | чистая управляемая библиотека без зависимости от установленного Excel/COM-интеропа |
| Хранение настроек | `DataContractJsonSerializer` (встроен в .NET Framework) | не требует отдельного NuGet-пакета для JSON |
| Шифрование пароля | Windows DPAPI (`System.Security.Cryptography.ProtectedData`) | пароль подключения хранится зашифрованным, привязан к пользователю Windows |

Проект — SDK-style `.csproj` (`Microsoft.NET.Sdk`) с `TargetFramework=net48`,
`Nullable=enable`, `ImplicitUsings=enable`, `LangVersion=latest`. Из-за
`LangVersion=latest` в коде используются современные конструкции языка C#
(record-типы, `init`-свойства, target-typed `new`), но они компилируются в IL,
совместимый с .NET Framework 4.8 — при условии, что в коде не используются
BCL-API, которых физически нет в net48 (see §9, «известные ограничения»).

`IsExternalInit.cs` — служебный файл-полифилл: .NET Framework не содержит тип
`System.Runtime.CompilerServices.IsExternalInit`, необходимый компилятору для
`init`-свойств и record-типов; объявлен вручную, чтобы сборка не падала на
старых версиях SDK/MSBuild, которые не подставляют его автоматически.

## 4. Полный функционал (текущее состояние)

### 4.1. Подключение к базе данных
- Диалог со списком сохранённых подключений (`ConnectionSettingsForm`):
  добавить/изменить/удалить/выбрать (двойной клик по строке = выбрать).
- Форма одного подключения (`ConnectionEditForm`): сервер, база, логин/пароль
  или Windows-аутентификация, кнопка «Проверить» (пробное подключение).
- Пароль хранится в `connections.json` в зашифрованном виде (DPAPI,
  `DataProtectionScope.CurrentUser`) — расшифровывается только на том же
  компьютере тем же пользователем Windows; при смене машины/пользователя
  пароль просто не восстановится (без падения — `Unprotect` ловит
  `CryptographicException` и возвращает пустую строку).
- При запуске программы автоматически применяется последнее использованное
  подключение, и сразу подгружаются справочники (группы, единицы измерения,
  налоговые ставки, существующие артикулы и штрих-коды).

### 4.2. Открытие документа
- Диалог выбора файла: `.xlsx`, `.xls`, `.csv`.
- `.xlsx`/`.xls` читаются через NPOI (с вычислением формул через
  `IFormulaEvaluator`); `.csv` — собственным построчным парсером с
  автоопределением разделителя (запятая/точка с запятой/таб) и поддержкой
  кавычек/экранирования.
- Весь документ читается в память один раз при открытии
  (`SpreadsheetDocument.Sheets: Dictionary<string, List<string[]>>`), дальше
  все операции (сопоставление, экспорт, автоархивация) работают с этим
  готовым представлением, без повторного чтения файла с диска.
- Выбор листа — выпадающий список. Строка заголовков задаётся либо полем
  «Строка с заголовками», либо кликом по нужной строке прямо в таблице
  предпросмотра документа. Импорт начинается со следующей строки.

### 4.3. Сопоставление колонок
- Таблица «Сопоставление колонок»: для каждой колонки документа — номер,
  заголовок, пример значения и выпадающий список «Назначение» с полями БД:
  Наименование (обязательно), Штрих-код, Группа, Артикул, Весовой (да/нет),
  Единица измерения, Налоговая ставка, Подакцизный (да/нет), УКТЗЕД.
- **Дедупликация выбора.** Поле, уже выбранное для одной колонки, пропадает
  из списка выбора для всех остальных колонок, пока выбор не снят — нельзя
  случайно сопоставить одно и то же поле дважды. Реализовано через
  перестроение `DataSource` каждой ячейки при каждом изменении грида
  (`MainForm.RefreshMappingComboOptions`), с флагом подавления рекурсии
  `_suppressMappingComboRefresh`.
- УКТЗЕД — необязательное поле: если колонка не сопоставлена или ячейка
  пуста, значение просто не заполняется (`ass2031` остаётся пустым).
- Поле «НДС, %» убрано из списка выбора (осталось в коде как устаревший,
  неиспользуемый путь разрешения — см. §4.5 и §8, пункт про `TargetField.Vat`).

### 4.4. Группа товара
- Если колонка «Группа» сопоставлена: значение ячейки, совпадающее с
  названием или кодом существующей группы (`gru2`, `gru2002 = 1`) —
  используется эта группа; значение, которого нет в справочнике — **группа
  создаётся в БД автоматически** (`SqlServerRepository.InsertGroup`:
  новый `gru2001` = `MAX(gru2001)+1`, `gru2002=1`, `gru2003=gru2001+100`,
  `gru2005=0`) и используется для этого товара; пустая ячейка — используется
  «Группа товаров по умолчанию».
- Новые группы создаются одной транзакцией перед вставкой товаров
  (`ImportOrchestrator.CreateMissingGroups`, вызывается первым шагом из
  `Import`), по одной записи на каждое уникальное отсутствующее название.
- Кнопка «Сопоставление групп товаров» (`ProductGroupMappingForm`) — список
  всех товаров текущего импорта с их итоговой группой; можно выделить
  несколько строк (Shift/Ctrl/Ctrl+A) и назначить им одну группу из БД сразу
  через выпадающий список «Для выделенных строк» + кнопку «Применить к
  выделенным». Ручной выбор имеет приоритет над автоматическим
  определением/созданием.

### 4.5. Налоговая ставка (НДС)
- Поле «Налоговая ставка» разрешается **только** через явное сопоставление,
  без попытки разобрать значение как число/процент. Кнопка «Сопоставление
  налоговых групп» (активна, когда поле сопоставлено) открывает список
  уникальных значений этой колонки в документе, где каждому назначается
  ставка из `nds1`. Для пустых ячеек или значений без сопоставления —
  «Налоговая ставка по умолчанию».
- Название строки в списке ставок берётся из `nds1002` (не из `nds1003`,
  которая хранит числовой процент и используется только служебно — для
  устаревшего авто-сопоставления по полю `TargetField.Vat`, которое больше
  не доступно для выбора через интерфейс, но код резолюции оставлен не
  удалённым ради совместимости со старыми сохранёнными профилями).

### 4.6. Единица измерения
- Кнопка «Сопоставление единиц измерения» (активна, когда колонка
  сопоставлена) — список уникальных значений документа, каждому назначается
  единица из `cls2` (`cls2002 = 100`). Явное сопоставление имеет приоритет
  над автоматическим поиском по названию/коду, который в свою очередь имеет
  приоритет над «Единицей измерения по умолчанию» (для пустых ячеек и
  значений без совпадения).

### 4.7. Подакцизность
- Кнопка «Сопоставление акцизности товара» (активна, когда колонка
  «Подакцизный (да/нет)» сопоставлена) — список уникальных значений, каждому
  назначается «Да»/«Нет»; это сопоставление имеет приоритет.
- Если явного сопоставления для значения нет — слова
  да/д/yes/y/1/true/истина → `ass1007 = 1`, `ass2010 = 1`; слова
  нет/н/no/n/0/false/ложь → `ass1007 = 0`, `ass2010 = 2` (как в исходном
  T-SQL скрипте — изначально было захардкожено `2` для всех товаров без
  исключения). Сравнение без учёта регистра, с обрезкой пробелов.
- Для пустых ячеек и нераспознанных значений — «Подакцизность по умолчанию».

### 4.8. Значения по умолчанию
Раздел «Значения по умолчанию»: группа, единица измерения, налоговая ставка,
весовой (да/нет), подакцизный (да/нет). Применяются, если соответствующая
колонка не сопоставлена, или значение в ячейке не распознано и не покрыто
явным сопоставлением (групп/единиц/ставок/акцизности). При запуске импорта
программа предупреждает, если фактически нужное значение по умолчанию не
выбрано, и даёт возможность отменить импорт.

### 4.9. Профили импорта
Строка заголовков, сопоставление колонок и пять значений по умолчанию можно
сохранить под именем и повторно применить для документа с такой же
структурой, но другим содержимым (например, регулярный прайс-лист от одного
поставщика). При выборе профиля всё подставляется автоматически; при
следующем запуске программы автоматически применяется последний
использованный профиль. **Не сохраняется в профиль**: явные сопоставления
значений (группы/единицы/налоговые ставки/акцизность) — они относятся к
конкретным значениям в конкретном файле, а не к его структуре.

### 4.10. Обработка штрих-кода
Раздел «Требуется решение по штрих-коду» появляется при нажатии «Начать
импорт», если есть строки без штрих-кода, с некорректным (не 8/12/13 цифр)
или с уже занятым другим товаром штрих-кодом. Для каждой строки (или сразу
для всех через «Применить ко всем») выбирается действие: сгенерировать
уникальный EAN-13, не импортировать строку, или ввести штрих-код вручную
(`ManualBarcodeForm`). После этого кнопка «Начать импорт» становится
«Импортировать».

Генерация EAN-13 (`BarcodeGenerator.GenerateUniqueEan13`): тело кода —
префикс `20` (зарезервирован GS1 для внутреннего использования) + 10
случайных цифр (генерируются по одной, так как диапазон `Random.Next` не
покрывает 10-значные числа целиком) + контрольная цифра по стандартному
алгоритму mod-10 GS1; при коллизии с уже занятыми кодами генерация
повторяется.

### 4.11. Автоматический архив сгенерированных штрих-кодов
Если при импорте хотя бы для одного товара штрих-код был сгенерирован
автоматически (не введён вручную и не был изначально корректным в
документе — различается полем `ImportRow.BarcodeWasGenerated`, которое
выставляется только внутри ветки `BarcodeAction.Generate` в
`ApplyBarcodeResolution`), программа **без участия пользователя** сохраняет
два файла рядом с `ProductsImport.exe`, в папке `generated_docs`:

- `generated_docs\full\<имя файла>_<дата>_<время>.xlsx` — точная копия
  исходного документа (все строки, все колонки, включая строки выше шапки),
  где заменена только ячейка штрих-кода для строк со сгенерированным
  значением; остальные ячейки — как в исходном файле.
- `generated_docs\generated_only\<имя файла>_<дата>_<время>.xlsx` — та же
  структура (строки выше и включая шапку сохраняются как есть), но в теле —
  только строки товаров, для которых штрих-код был сгенерирован.

Имя файла строится как `<имя исходного файла без расширения>_<yyyy-MM-dd>_
<HH-mm-ss>.xlsx` (`GeneratedDocsStore.BuildFilePath`). При каждом импорте
(даже если в этот раз ничего не генерировалось) программа также проверяет
обе подпапки и удаляет файлы старше одного месяца
(`GeneratedDocsStore.CleanupOldFiles`, `DateTime.Now.AddMonths(-1)`) —
удаление файла, занятого другим процессом, просто откладывается до
следующего запуска (ошибки `IOException`/`UnauthorizedAccessException`
проглатываются). Вся эта логика выполняется в фоновом потоке
(`Task.Run`) и не блокирует интерфейс; сбой записи/очистки не считается
ошибкой импорта — показывается отдельное предупреждение, а результат
импорта в БД при этом не теряется.

Окно результата импорта показывает точные пути к обоим сохранённым файлам
(если они были созданы в этом запуске).

### 4.12. Артикул
Если в документе нет артикула, или он не указан в строке — автоматически
берётся наименьший свободный номер `ass1001` (`ArticleAllocator`, учитывает
уже занятые артикулы из БД и явно указанные артикулы других строк текущего
импорта). Если указанный в документе артикул уже занят — строка помечается
ошибкой.

### 4.13. Импорт и обработка ошибок
- Каждая строка импортируется в собственной транзакции (`ass1`+`ass2`+
  `ass3`+`ass4`), поэтому ошибка одной строки не блокирует остальные.
- Строки, которые не удалось импортировать (нет наименования, не удалось
  определить группу/единицу/ставку, конфликт артикула, ошибка БД, штрих-код
  не был разрешён, пропущено пользователем) собираются в список
  (`ImportSummary.Errors`) и могут быть сохранены в отдельный `.xlsx` —
  с исходными данными строки и причиной ошибки — для исправления и
  повторного импорта (`ErrorReportService`, кнопка «Сохранить ошибки в
  Excel...» в окне результата).
- Окно результата (`ImportResultForm`) показывает: всего строк, успешно
  импортировано, пропущено пользователем, не импортировано из-за ошибок,
  таблицу ошибок построчно, и (если применимо) путь к автоматически
  сохранённым файлам со сгенерированными штрих-кодами.

### 4.14. Язык интерфейса
Кнопка «Настройки...» в главном окне открывает выбор языка: русский,
украинский, румынский (`SettingsForm`). Весь текст интерфейса вынесен в один
файл (`Localization/Strings.cs`) с переводом на все три языка — подробнее в
§7. Выбранный язык сохраняется в `settings.json` и применяется **после
перезапуска программы** (см. §7 — почему именно так).

### 4.15. Хранение настроек
Все пользовательские настройки — подключения (`connections.json`), профили
импорта (`import_profiles.json`), последнее состояние (`settings.json`:
последнее подключение, последний профиль, язык) — хранятся в JSON-файлах в
папке `config` **рядом с `ProductsImport.exe`**, а не в `%AppData%`, так что
переносятся вместе с программой при переносе на другую машину (кроме
зашифрованного пароля — он привязан к DPAPI конкретного пользователя
Windows). Если программа установлена в защищённую системную папку (например,
`Program Files`), для записи в `config` понадобятся права на запись в папку
программы.

## 5. Поток выполнения импорта (конвейер)

1. **`TryGetDocumentLayout`** — читает текущий лист, проверяет корректность
   строки заголовков, возвращает `(HeaderRow, DataRows, ColumnCount)`.
2. **`TryBuildMappingFromGrid`** — собирает `ColumnMapping` из грида
   сопоставления колонок, проверяет обязательность «Наименование» и
   предупреждает об отсутствии «Штрих-код».
3. **`ImportOrchestrator.BuildRows`** — превращает сырые строки документа в
   `List<ImportRow>`, пропуская полностью пустые строки. `SourceRowNumber`
   каждой строки — это её настоящий 1-based номер в исходном листе (что
   используется позже для сопоставления с полным списком строк документа
   при построении архивных файлов).
4. **`ImportOrchestrator.Analyze`** — для каждого потенциально
   нуждающегося в умолчании поля (группа/единица/ставка/весовой/акцизный)
   определяет, понадобится ли фактически значение по умолчанию (`NeedsAnalysis`),
   учитывая явные сопоставления значений.
5. **`MainForm.TryCollectDefaults`** — считывает выбранные в интерфейсе
   значения по умолчанию, предупреждает (с возможностью отмены), если
   реально нужное умолчание не выбрано.
6. **`ImportOrchestrator.Resolve`** — для каждой строки разрешает
   наименование, штрих-код (или помечает `BarcodeNeedsResolution`), группу
   (включая `PendingNewGroupName` для новых групп), единицу, НДС, весовой,
   акцизный, УКТЗЕД; затем одним проходом раздаёт артикулы
   (`ResolveArticles`).
7. **`MainForm.ApplyGroupOverrides`** — накладывает ручные правки группы из
   окна «Сопоставление групп товаров» поверх автоматического разрешения.
8. Если есть строки с `BarcodeNeedsResolution == true` — показывается раздел
   «Требуется решение по штрих-коду»; импорт приостанавливается до тех пор,
   пока пользователь не разрешит каждую строку
   (`TryApplyBarcodeSection` → `ApplyBarcodeResolution` для каждой).
9. **`ImportOrchestrator.Import`**:
   - `CreateMissingGroups` — создаёт в БД все недостающие группы одной
     транзакцией;
   - для каждой строки без ошибки — отдельная транзакция `InsertProduct`
     (`ass1`+`ass2`+`ass3`+`ass4`); ошибки SQL откатывают только эту
     транзакцию и попадают в список ошибок;
   - строки с ошибкой (включая неразрешённый штрих-код) сразу уходят в
     `ImportSummary.Errors`, не доходя до БД.
10. **`MainForm.ArchiveGeneratedBarcodeReports`** (в фоновом потоке) —
    если был хотя бы один сгенерированный штрих-код, пишет оба архивных
    файла (§4.11) и в любом случае чистит `generated_docs` от файлов старше
    месяца.
11. **`ImportResultForm`** показывает итог, пути к архивным файлам (если
    есть) и предлагает сохранить список ошибок.
12. После закрытия окна результата справочники (группы/единицы/ставки/
    занятые артикулы и штрих-коды) перечитываются из БД заново
    (`RefreshReferenceDataAsync`), чтобы учесть только что созданные группы
    и товары при следующем импорте в той же сессии.

## 6. Соответствие таблицам БД

Логика вставки повторяет исходный T-SQL скрипт импорта:

- **`ass1`** (`ass1001..ass1007`): артикул (тот же код для `ass1001` и
  `ass1002`), наименование, НДС (`nds1001`), единица измерения (`cls2001`,
  где `cls2002 = 100`), весовой, подакцизный (`ass1007`: 1/0).
- **`ass2`**: дублирует артикул/наименование; `ass2010` — подакцизный
  (**1** = подакцизный, **2** = нет — так было захардкожено в исходном
  T-SQL скрипте для абсолютно всех товаров; теперь зависит от резолюции
  акцизности каждой строки); `ass2031` — УКТЗЕД (пусто, если не
  сопоставлено/не заполнено); остальные колонки — те же константы по
  умолчанию, что и в исходном скрипте.
- **`ass3`**: штрих-код товара (`ass3002`).
- **`ass4`**: привязка товара к группе (`ass4003 = gru2001`, где
  `gru2002 = 1`).
- **`gru2`**: новая группа создаётся автоматически (`gru2002 = 1`,
  `gru2003 = gru2001 + 100`, следующий свободный `gru2001`), когда значение
  колонки «Группа» не совпадает ни с одной существующей.
- **`cls2`** (`cls2002 = 100`), **`nds1`** (название — `nds1002`, процент —
  `nds1003`, использующийся только для устаревшего авто-сопоставления по
  проценту) читаются только для справочников, не изменяются приложением.

## 7. Локализация

Введена система локализации без внешних зависимостей:

- `Localization/Language.cs` — `enum Language { Russian, Ukrainian, Romanian }`.
- `Localization/Strings.cs` — статический словарь `Dictionary<string, string[]>`,
  ключ — стабильный строковый идентификатор, значение — массив из трёх строк
  (индексы совпадают с порядком объявления `Language`). Метод `Strings.T(key)`
  возвращает перевод для `Strings.Current`; перегрузка `Strings.T(key, args)`
  форматирует строку через `string.Format`. Если ключ не найден — возвращается
  сам ключ (а не исключение), что не ломает интерфейс при опечатке.
- `Program.cs` выставляет `Strings.Current` из `AppSettingsStore.Load().Language`
  **до** создания `MainForm`.
- Каждая форма читает `Strings.T(...)` в инициализаторах полей и в
  конструкторе — то есть **один раз**, в момент создания окна. Из этого
  следует ключевое архитектурное ограничение: **смена языка в «Настройки...»
  применяется только после перезапуска программы** — диалог явно
  предупреждает об этом текстом. Полное «живое» переключение языка без
  перезапуска потребовало бы отдельного метода пересборки текста для каждого
  элемента управления в каждом окне — сознательно не реализовано ради
  простоты.
- Все 149 строк интерфейса (кнопки, подписи, заголовки окон, тексты
  сообщений, заголовки колонок таблиц, сообщения об ошибках строк импорта,
  текст листа Excel-отчётов) заведены через `Strings.T`; проверено, что
  каждый используемый в коде ключ присутствует в словаре и наоборот (нет
  неиспользуемых ключей).
- Данные из базы (названия групп, единиц измерения, названий налоговых
  ставок) **не переводятся** — это содержимое БД, а не текст интерфейса.

## 9. Известные особенности и ограничения

- **Компиляция не проверялась автоматически в большинстве итераций** — в
  среде разработки Claude Code (где вносилась часть правок) нет
  установленного .NET SDK; код проверялся только вычиткой. Это стало
  причиной инцидента из п. 12 (использование `GetValueOrDefault`,
  отсутствующего в net48). Любые дальнейшие правки стоит обязательно
  собирать локально в Visual Studio/`dotnet build` перед тем, как считать
  готовыми.
- **net48-совместимость BCL API** — при добавлении нового кода нужно
  проверять, что используемые методы `Dictionary`/`LINQ`/`string` реально
  существуют в классическом .NET Framework, а не только в .NET Core/5+/
  Standard 2.1 (типичные ловушки: `GetValueOrDefault`, `TryAdd`,
  `Remove(key, out value)`, `DistinctBy`/`MaxBy`/`MinBy`/`Chunk`,
  `Path.Join`, `string.Contains(char)`).
- **`DataGridViewComboBoxColumn`** с произвольными (не примитивными)
  объектами в качестве значений ячеек должен связываться через `DataSource`
  + `DisplayMember` + `ValueMember` (при необходимости — через обёртку
  `(Value, Display)`), а не через голую `Items`-коллекцию — последняя
  ненадёжна при коммите выбора пользователя (см. п. 9 истории изменений).
- **Язык интерфейса** применяется только после перезапуска программы —
  архитектурное решение, а не недосмотр (см. §7).
- **`TargetField.Vat`** (устаревшее поле «НДС, %») оставлено в коде и в
  `ImportOrchestrator` ради совместимости со старыми сохранёнными профилями
  импорта, но полностью убрано из списка выбора в интерфейсе — новые
  сопоставления на него указывать не могут.
- **`ass1007`** продолжает получать `1`/`0` по значению акцизности (как и
  раньше), в то время как `ass2010` теперь получает `1`/`2` — это
  сознательно разные кодировки одного и того же признака, соответствующие
  поведению исходного T-SQL скрипта; при сомнении в правильности значения
  `ass1007` для конкретной схемы БД стоит свериться с реальным скриптом.
- **Удаление файлов в `generated_docs`** — лучшее усилие (best-effort):
  файл, открытый другим процессом в момент очистки, просто остаётся до
  следующего запуска, ошибка не показывается пользователю.
- **Шифрование пароля подключения** через DPAPI привязано к паре
  компьютер+пользователь Windows — сохранённые подключения не переносятся
  между машинами с паролем; при переносе `connections.json` на другой
  компьютер пароль нужно будет ввести заново.
